## Cursor Cloud specific instructions

- Stack: TanStack Start + React 19 + Vite 8, styled with Tailwind v4 / shadcn. The backend is a **remote hosted Supabase** project. Copy `.env.example` → `.env` and fill `VITE_SUPABASE_*` / `SUPABASE_*` (publishable key is enough for most UI work; `SUPABASE_SERVICE_ROLE_KEY` and `LOVABLE_API_KEY` are server-only). There is no local database to start — the app talks directly to the remote Supabase instance.
- Package manager is **Bun** (`bun.lock`), not npm/yarn. Bun is installed at `~/.bun/bin` and is on `PATH` via `~/.bashrc`; the update script runs `bun install`.
- Run the app in dev mode with `bun run dev` (Vite dev server on `http://localhost:8080`, SSR via TanStack Start). Standard scripts are in `package.json` (`dev`, `build`, `lint`, `qa`).
- Tests/QA: `bun run qa` runs several standalone checks (`qa:ai`, `test:ai-contract`, `test:resume-diff`, `test:templates`, `check:rtl`) **plus** `qa:routes` and `check:routes-shell`, which fetch every route from a **running dev server on port 8080**. Start `bun run dev` first, or the route checks fail with `fetch failed`. Override the base URL with `QA_BASE_URL` if needed.
- Prefer not to mass-reformat; run `bun run lint` / `bunx prettier --check .` when touching files. `src/routeTree.gen.ts` is auto-generated by the TanStack router plugin — do not commit incidental changes to it.
- Auth: store mutations (`updateProfile` / `createResume` / …) call `ensureSession()` (refresh if needed) to close the post-signup JWT race that previously caused intermittent 401s on onboarding finish. Email confirmation may still be disabled on the remote Supabase project (dev convenience); enabling it is a Dashboard setting (`Authentication → Providers → Email → Confirm email`), not a code change. Supabase rejects weak/pwned passwords — use a strong password in tests.
- New SQL under `supabase/migrations/` must be applied to the remote project (Lovable Cloud sync or Supabase SQL editor). Adding a migration file alone does not mutate the live DB.
- Admin UI is client-gated, but privileged reads/writes are enforced by Supabase RLS (`has_role(..., 'admin')`) and `admin_set_user_role`. A non-admin may open `/admin` only if they spoof client state; cross-tenant data and admin writes still fail at Postgres.
