## Cursor Cloud specific instructions

- Stack: TanStack Start + React 19 + Vite 8, styled with Tailwind v4 / shadcn. The backend is a **remote hosted Supabase** project; credentials live in the committed `.env` (`VITE_SUPABASE_*`). There is no local database to start — the app talks directly to the remote Supabase instance.
- Package manager is **Bun** (`bun.lock`), not npm/yarn. Bun is installed at `~/.bun/bin` and is on `PATH` via `~/.bashrc`; the update script runs `bun install`.
- Run the app in dev mode with `bun run dev` (Vite dev server on `http://localhost:8080`, SSR via TanStack Start). Standard scripts are in `package.json` (`dev`, `build`, `lint`, `qa`).
- Tests/QA: `bun run qa` runs several standalone checks (`qa:ai`, `test:ai-contract`, `test:resume-diff`, `test:templates`, `check:rtl`) **plus** `qa:routes` and `check:routes-shell`, which fetch every route from a **running dev server on port 8080**. Start `bun run dev` first, or the route checks fail with `fetch failed`. Override the base URL with `QA_BASE_URL` if needed.
- `bun run lint` currently reports many pre-existing `prettier/prettier` formatting errors in the committed source. This is the repository's existing state, not an environment problem; do not mass-reformat unless asked (`bun run format` would rewrite files).
- `src/routeTree.gen.ts` is auto-generated by the TanStack router plugin and gets rewritten when the dev server runs; do not commit incidental changes to it.
- Signup email confirmation is disabled on the remote Supabase project, so email/password sign-up returns a session immediately and you can go straight from `/auth?mode=signup` to onboarding/dashboard. Supabase enforces password strength (weak/pwned passwords are rejected), so use a strong password in tests. Note: the onboarding "finish" step can intermittently 401 right after signup; creating a resume from the dashboard (`/resumes/new`) works reliably.
